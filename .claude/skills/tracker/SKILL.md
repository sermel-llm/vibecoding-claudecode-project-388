## Шаги
1. Запомни дату и время начала прогона по московскому времени (UTC+3).
2. Прочитай предыдущий прогон через MCP-сервер `github`:
   - получи список файлов в корне `sermel-llm/tracker-data`;
   - выбери последний по имени файл вида `ГГГГ-ММ-ДД.json` (имена сортируются как даты) — это предыдущий прогон, даже если он за сегодня;
   - если таких файлов нет — это первый запуск, сравнивать не с чем;
   - если файл не прочитался или это не корректный JSON — сравнение пропусти и сообщи об этом в выводе.
3. Для каждой ссылки из списка по порядку вызови скилл `extract-price` (через инструмент Skill) — отдельный вызов на каждую ссылку.
   - Не пиши скрипты и не извлекай цены сам, даже если это кажется быстрее: логика извлечения должна оставаться только в `extract-price`, чтобы его улучшения сразу работали в трекере.
   - Если для ссылки пришёл `{"error": ...}`, не останавливайся — запиши ошибку и переходи к следующей ссылке.
4. Собери результаты в одну таблицу.
5. Сравни текущий прогон с предыдущим (если он есть):
   - сопоставляй строки по `url`;
   - фактическая цена = `sale_price`, если он не `null`, иначе `regular_price`;
   - если в текущей или в прошлой строке есть `error` — цены не сравнивай, отметь состояние проверки (сломалась / восстановилась / по-прежнему ошибка);
   - для остальных строк сравни фактическую цену, наличие скидки и `has_credit`;
   - отдельно отметь ссылки, которые появились или исчезли по сравнению с прошлым прогоном.
6. Примени к найденным изменениям правила значимости из файла `KNOWLEDGE.md` в корне проекта. Оставь только значимые изменения.
7. Сохрани текущий прогон в репозиторий через MCP-сервер `github`:
   - репозиторий: `sermel-llm/tracker-data`, ветка `main`;
   - путь: корень репозитория, имя файла `ГГГГ-ММ-ДД.json` по дате начала прогона (например, `2026-11-10.json`);
   - если файл за эту дату уже есть — перезапиши его новым прогоном (предыдущая версия останется в истории коммитов);
   - сообщение коммита: `Run ГГГГ-ММ-ДД ЧЧ:ММ: N links, M errors`;
   - содержимое — JSON такого вида:
     ```json
     {
       "date": "2026-11-10 11:37",
       "rows": [
         {"item": "Crucial CT16G56C46S5", "url": "https://...", "regular_price": 33564, "sale_price": null, "has_credit": true, "error": null}
       ]
     }
     ```
   - в `rows` — строки таблицы в том же порядке; у строки без ошибки `"error": null`, у строки с ошибкой `regular_price`, `sale_price` и `has_credit` — `null`, в `error` — причина.
   - только прямые двойные кавычки `"`, числа без кавычек.
   - Не клонируй репозиторий и не используй git или gh в терминале — только инструмент MCP-сервера `github` для создания или обновления файла.
8. Если сохранить не удалось — всё равно покажи результат и сообщи причину ошибки сохранения.
9. Получи текст сводки у субагента `tg-summary` (через инструмент Agent):
   - передай ему дату и время прогона, признак первого прогона и список значимых изменений и событий проверки — по одной строке, с товаром, доменом, прошлым и новым значением и готовым процентом;
   - сам текст сводки не составляй — оформление целиком в `tg-summary`;
   - если субагент недоступен или вернул пустой ответ — составь сводку сам в формате из `.claude/agents/tg-summary.md` и отметь это в выводе.
10. Отправь полученный текст через `send.py` в корне проекта, передавая его через here-doc:
    ```bash
    python3 send.py "$(cat <<'EOF'
    <текст от tg-summary>
    EOF
    )"
    ```
    - если `send.py` вывел ошибку — не повторяй отправку, сообщи ошибку в выводе; прогон уже сохранён.


## Выход
1. Строка сравнения: «Сравнение с прогоном ГГГГ-ММ-ДД ЧЧ:ММ», «Первый запуск — сравнивать не с чем» или причина, почему сравнение не удалось.
2. Значимые изменения — по одной строке на изменение, в формате из `KNOWLEDGE.md` в корне проекта, сгруппированные по товару (`item`). Если значимых изменений нет — строка «Значимых изменений нет».
3. Не удалось проверить — ссылки с `error` в текущем или прошлом прогоне, по правилам блока «Ошибки проверки» из `KNOWLEDGE.md` в корне проекта.
4. Итог: сколько ссылок обработано, сколько с ошибкой, сколько значимых изменений.
5. Ссылка на сохранённый файл в tracker-data или причина, почему сохранить не удалось.
6. Отправлена ли сводка в Telegram («Отправлено в Telegram» или текст ошибки) и кто её составил (`tg-summary` или основная модель).

Не добавляй предположений о причинах изменений — только факты по правилам из `KNOWLEDGE.md` в корне проекта.

Полную таблицу цен выводи, только если пользователь её попросил. Её формат — одна строка на каждую ссылку из списка, в том же порядке:

| date | item | url | regular_price | sale_price | has_credit | error |
|---|---|---|---|---|---|---|
| 2026-11-10 14:30 | Crucial CT16G56C46S5 | https://www.nix.ru/... | 33564 | null | true | |
| 2026-11-10 14:30 | Samsung MZ-VAP1T0BW | https://www.oldi.ru/... | | | | страница с капчей |

- `date` — дата и время начала прогона в формате `ГГГГ-ММ-ДД ЧЧ:ММ`, одинаковые для всех строк.
- `item` — название товара из заголовка группы в списке, к которой относится ссылка.
- Значения цен бери из ответа `extract-price` без изменений; при ошибке поля цен пустые, в `error` — причина.
